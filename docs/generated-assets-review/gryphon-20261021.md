# Gryphon: shore palette and articulated chapter checkpoints

## Scope and source selection

`generatedGryphonSvg(id, style, demo)` accepts only `gryphon`, `engraved`, and
`lobster-quadrille`, `mock-turtle`, `duchess` or `trial`. The Trial dream reuses
the coherent whole source. The Duchess landing uses the identical neutral
chapter assembly to preserve their shared opening illustration, but adds no
raised-paw overlay or limb action. Their
consumer audit, tint differences and unexecuted browser checks are recorded in
[`actor-consumers-20261021.md`](actor-consumers-20261021.md).
Flat/paper, unknown consumers and other
figures keep the existing renderer. The registry, `OWN_COLOURS`, original
`GRYPHON_SVG`, `GRYPHON_PAWS`, chapter timeline and shore tokens are unchanged.

The first whole master had a corrected single tail but an orange/gold body.
It was not accepted as a shore-palette replacement. An image-generation edit
produced the selected 1306 × 1205 whole source with muted grey-brown body and
aged-paper feathers, retaining one tail, four legs, its pose and transparent
canvas. This is a fixed shore-tint engraving, not a live CSS-recolourable
image. The exact original vector and its CSS palette expressions remain the
pending/error fallback and the other art styles.

All four selected sources, complete edit prompts, original dimensions, alpha
bounds, SHA-256 digests and placement parameters are recorded in
`src/assets/images/generated-layers/gryphon-provenance.json`. WebP encoding
used quality 92, method 6, unchanged canvas and byte-identical alpha. No source
was programmatically resized, cropped, recoloured or painted.

## Quadrille whole figure

The 240 × 220 logical box stays unchanged. Uniform scale is `220 / 1205`;
horizontal centring uses the complete source width, and visible sole baseline
source y1172 maps to logical y220. Faint alpha below the principal sole extends
nine source pixels further; the existing generated-art overflow rule preserves
that fringe without changing the layout box. The outer dancer/lead transform,
shadow and all scene choreography remain outside the adapter.

The complete original vector stays visible until the one whole image decodes.
The whole asset is 461,910 bytes. See `gryphon-quadrille-20261021.png`: exact
shore-colour original, accepted generated whole, and the deliberately rejected
whole-plus-original-paws composition. The rejected example is not a runtime
consumer.

## Mock Turtle chapter: independent forelegs

Reusing the whole image would produce extra forelimbs when the chapter's
original paws rise. Hiding those paws instead would silently remove the
face-hiding action. Neither shortcut is used.

Three coherent sources were generated from the selected whole master:

- Body: 1305 × 1205, two hind legs, no fixed forelegs, one tail.
- Near foreleg: 1305 × 1205, original canvas placement, one foreleg and paw.
- Far foreleg: 1416 × 1111. The generator changed its canvas and placement;
  the adapter therefore maps it explicitly with uniform factor 0.91 and
  source-coordinate offset (38,217), rather than assuming a matching canvas.

Both independent forelegs are visible at rest. Their roots remain covered by
chest feathers while they rise, and both paws cover the visible eye at full
hide. Draw order is body, far foreleg, near foreleg. Source near pivot (795,660)
rotates by −137° × `--hide`. Source far pivot (1005,770) rotates by −158° ×
`--hide` and lifts −130 source pixels × `--hide`. All positions, pivots and the
lift are converted to the same logical root coordinates. The original scene
owns `--hide`, including reversal, pause and reduced-duration motion; this
adapter adds no timer or autonomous animation.

All three images must decode before the generated body/legs appear. Only a
ready chapter rig suppresses its original sibling `svg.mt__paws`. Pending or
failed images keep the original body and both original animated paws together.
The chapter assets total 479,810 bytes.

`gryphon-chapter-motion-20261021.png` is a widened, runtime-markup-derived
composition at hide 0, 0.35, 0.7 and 1. It preserves the actual per-layer image
geometry and the stylesheet's angles/lift. It omits the unchanged outer scene
transform and is not a browser screenshot. Independent source, geometry and
code review found no static blocker: no extra tail/legs, floating shoulder
roots, exposed cut faces or missed eye coverage. The older
`gryphon-layer-candidates-20261021.png` records why unmeasured layer placement
was rejected, not the selected assembly.

## Integration and verification

The parent integrates the renderer through `art.ts` and imports
`generated-gryphon.css` only from the runtime `generated-rig.ts` loader. The
renderer module itself has no CSS import, so build-time art generation remains
valid. Actual `figure()` routing and the runtime-only import are tested.

- 18 focused Vitest assertions passed across Gryphon renderer/routing,
  source-canvas provenance and the existing shared atomic-loader tests.
- Scoped Biome checks passed. TypeScript checking passed before a concurrent
  browser-test addition; the latest shared-tree check reports ten TS2532
  diagnostics in `tests/play/generated-mushroom-preview.spec.ts` at lines
  192, 196, 197, 201 and 204. The integration owner was informed. No Gryphon
  TypeScript diagnostic was reported.
- Every WebP was checked against its original PNG for equal dimensions and

- Offline compositions and independent source/code/geometry review completed.

The integration owner runs aggregate validation after concurrent work settles.
Browser playback, delayed/failed image flows in a real browser, phone/desktop
composition, actual reverse scrolling, pause and reduced-motion behaviour are
not claimed as verified here. They remain scoped visual/runtime checkpoints,
not reasons to stop other image work. The four runtime WebPs add 941,720 bytes
in total; this is source-intake work, not delivery-size optimisation or a
performance-budget pass.
