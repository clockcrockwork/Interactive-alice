# Text and translation pipeline

Interactive Alice is meant to be read and played in any language, so visible
text is never written into scene code. This document describes how the text
layer is organised, how a language is added, and how the child-friendly
retelling is written.

It is the canonical document for the text model. How the experience refers to
this text is a separate contract, documented in
[`text-experience-binding.md`](text-experience-binding.md).

## 1. Four layers

| Layer | Path | Contains | Who writes it |
| --- | --- | --- | --- |
| Source | `text/raw/` | The original 1865 English, one file per chapter, untouched | Generated by `scripts/fetch-source-text.py` |
| Structure | `text/story/chNN.structure.json` | Story-section order, segment order, speaker, segment kind. No visible text | Authored once per chapter |
| Text | `text/locales/<locale>/chNN.json` | One short sentence per segment id, plus chapter and section titles | Adapter / translator |
| Config | `text/locales.json` | The locale list: role, reading level, per-sentence budget, writing direction, line-break keyword, whether spaces are content | Maintainer |
| Registry | `text/characters.json` | Every speaker a structure file may name | Maintainer |

The split matters because of the product rule that scene logic and visible text
stay separable. A runtime scene names the segment ids it stages, then asks the
locale layer for the words in the active language. Adding Korean means adding one
directory of JSON, with no change to any animation.

### Story sections are not runtime Scenes

A **story section** divides the *text* while a chapter is being adapted. A
runtime **Scene** divides the *experience*. They are different concepts, they
may disagree about where boundaries fall, and chapter 1 already shows it: the
sections `the-hole`, `the-fall` and `landing` are staged as one Rabbit Hole
Scene. Nothing in `text/` refers to scenes, shots, or beats; see
[`text-experience-binding.md`](text-experience-binding.md).

### Why the original stays separate

`text/raw/` is a read-only input and is never edited. `scripts/check-text.py`
verifies every raw file against the checksums in `text/raw/manifest.json`, so
an accidental edit fails the check. Every adaptation lives in the text layer,
which keeps the original auditable next to the retelling.

## 2. Segments

A segment is **one short sentence**. That is the unit the experience animates,
reveals on scroll, speaks aloud, and highlights, so it is also the unit of
translation. Long sentences are split into several segments instead of being
carried across languages as one block.

Segment ids look like `ch01.s0420`:

- the chapter prefix never changes;
- numbers increase in steps of ten, so a sentence can be inserted later
  without renumbering anything or breaking other languages;
- an id, once published, is permanent. Changing the wording of a segment keeps
  its id. Dropping a beat means deleting the id from every language at once.

Each structure entry also carries:

- `section` — the story section the segment belongs to;
- `kind` — `narration`, `dialogue`, `thought`, or `sound`;
- `speaker` — required for dialogue and thought, so voices, bubbles, and
  typography can differ per character without parsing text.

## 3. Writing rules

### The base text: `en-simple`

The 1865 original is not a book for small children. Its sentences run long, its
jokes are Victorian, and several passages assume a reader who already knows the
period. So the English in this project is itself an adaptation, written from
the original rather than copied from it, at roughly the reading level of the
nursery version of the story.

Rules for `en-simple`:

- one idea per sentence, and at most about fifteen words;
- plain everyday words, and no inverted or archaic phrasing;
- keep the story beats, the images, and the jokes that survive simplifying;
- keep Alice's voice curious and matter-of-fact rather than explained;
- replace a unit or reference a child cannot picture with one they can;
- never describe the artwork; the scene does that.

**Every other language is translated from `en-simple`, not from the 1865
text.** That keeps the reading level consistent across languages and means a
translator never has to decide how to simplify Victorian English.

### Translations

- Translate sentence by sentence, keeping the segment boundaries. If a
  language truly needs two sentences for one segment, fix it in the structure
  so every language gains the same extra segment.
- Match the reading level of the locale's target age rather than the English
  word order.
- Stay inside the locale's `maxChars` budget. The budgets exist because
  segments appear as on-screen lines in animated scenes, not as flowing
  paragraphs.
- Keep names consistent: Alice, Dinah, the White Rabbit. Record a local
  convention in the locale's `notes` field when a language needs one.
- Nonsense, puns, and rhymes get a local equivalent that lands the same joke,
  not a literal gloss.

### Japanese specifics

`ja` targets lower-primary readers: mostly kana, only simple kanji, and spaces
between phrases to help a new reader chunk the line. Spaces are part of the
text, not formatting, so they are stored in the JSON and the locale entry sets
`significantSpaces`. Nothing downstream may trim, collapse, or re-wrap them.

### One sentence per segment, with one exception

A segment is one line of text, normally one sentence. A paired or repeated cry
stays one segment, because splitting it would stage the halves separately. The
checker lists every multi-sentence segment as a todo line rather than failing, so
the set stays small and visible; there are four per language today.

## 4. Adding a language

1. Add an entry to `text/locales.json` with its name, `role: "translation"`, a
   `maxChars` budget, its writing direction and line-break keyword, whether its
   spaces are content, and a note about the intended reading level.
2. Create `text/locales/<locale>/chNN.json` for each finished chapter, copying
   the segment ids from the chapter structure.
3. Run `python3 scripts/check-text.py`.

The checker reports an untranslated chapter as a `todo:` line rather than an
error, so a language can ship chapter by chapter.

### What an unfinished translation means for the site

Publishability is derived from this layer, not declared by a flag:

- a **part page** is generated for a language when every chapter its scenes stage has
  text in that language;
- **every language in the registry keeps its `/<locale>/` entry**, translated or not.
  A language that is behind has fewer documents, not a smaller place in the site: the
  entry lists the parts it can be read in as links, and the ones it cannot as items
  marked `data-available="false"`, titled in the base locale because this language has
  no title for them yet;
- the entry is also in `manifest.json`, carrying every part **in story order** with an
  `available` flag, so a test or a later index reads what a language offers instead of
  parsing HTML, and reads it in the story's order. The entry markup is in the same
  order: translation does not advance front to back, so a language may well have the
  second part and not the first;
- the **base locale** is the exception: missing text there is a hard error, since
  there is nothing for the other languages to be translated from;
- the build logs every part it skipped and why, so a gap is visible rather than quiet.

So adding a scene that stages chapter 2 never breaks the English build because the
Japanese chapter 2 is still being written.

#### What a reader meets

A bookmark or a shared link to `/<locale>/` keeps working while that language is
behind, which is why the entry is generated unconditionally: the alternative loses a
URL every time a new chapter is staged ahead of its translations.

A link to a part page that does not exist yet is a genuine 404, and deliberately so.
It is not rewritten to another language: silently serving English to someone who
asked for Japanese is worse than an honest missing page. The entry never links such a
part, so a 404 means a hand-typed or outdated URL rather than a path through the site.

## 5. Adding a chapter

1. Read the original in `text/raw/`.
2. Break it into story sections, then into one-sentence segments, and write
   `text/story/chNN.structure.json`.
3. Write the `en-simple` text for every segment.
4. Translate into the other locales.
5. Run `python3 scripts/check-text.py`.

## 6. Checks

```
python3 scripts/check-text.py
```

It verifies the raw files against their checksums, the structure's ids and
ordering, section and segment parity between every locale and the structure, and
that each line of text is a single sentence within budget.

Both checkers validate every file against its schema in `schema/` before
applying their own rules. `scripts/check-experience.py` covers the other side of
the boundary: that the experience layer's segment references exist, are owned
once, and stay in reading order across the whole scene list.
